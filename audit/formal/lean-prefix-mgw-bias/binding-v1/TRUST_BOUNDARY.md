# Trust and source-only limits

This is an author source proposal. Independent-first review, actual control execution, new production replay, hosted evidence and public adoption remain open. AST reading and SHA-256 comparisons are source inventory work; no adapter, helper, policy, Runtime, supervisor or control module was imported or executed in this lane. No Lean, kernel, test, PDF or Git mutation occurred here.

The accepted mathematical source and the project-defined transport are distinct. Five existing finite categorical bias statements receive no new theorem credit from this package. The source-to-paper, source-to-formal, kernel validity, dependency object authenticity, executable refinement, Rust/Python/binary64 accuracy, estimator calibration, variance, confidence coverage, optional stopping, transformed/same-sample/dependent-row validity, continuous/hyperbolic transfer and application utility edges remain separate. No new novelty or performance claim is made.

Load-bearing source bytes are pinned before dynamic helper loading and recaptured through the unchanged descriptor-based Snapshot. It requires canonical regular single-link files and checks device/inode/mode/link count/size/time identity and bytes before and after capture. Source and produced objects are retained and repeatedly checked; saved raw inputs, commands, streams and result artifacts are required. This is bounded filesystem observation under stable-input assumptions, not atomic filesystem custody, a sandbox or authenticity evidence.

The root's reviewed plan and adoption receipt are trust inputs. An owner who rewrites sources, receipts and their pins together can forge that custody layer. Model author/reviewer agreement is advisory and not human, institutional, tool, data or custody independence. A different filename, process or Python mode is not an independent mathematical proof. The staged positive/negative objects and per-command evidence need root's direct inspection.

Exactly five current root source pins remain in unchanged Runtime: two checker helpers, Lean toolchain declaration, lakefile and lake manifest. The explicit NatInt import pin adds a sixth source file. Before production, the unchanged base helper checks Lean 4.33.0, the exact lakefile/manifest and nine package checkouts at their pinned revisions. The binaries have separately registered byte hashes. Dynamic package library paths are built from that exact package registry; ambient LEAN_PATH is not inherited. The thirty local proof modules are rebuilt in a fresh directory. Package library objects and the tool/kernel/OS remain trusted; no byte hash or clean checkout proves their authenticity or source correspondence.

The unchanged Runtime performs process-group sampling and cooperative resource enforcement. macOS lacks the same address-space cap; Lean's own memory argument and sampled RSS remain bounded observations. Runtime source hashing can consume time between caller deadline checks and Popen. The outer supervisor addresses that route through its cleanup reserve and refusal semantics, without claiming atomic launch/deadline enforcement. Scheduling, blocked native/OS operations, sampling gaps and surviving descendants can defeat timely cleanup; resulting uncertainty or late closure is failure, never successful killing. Only an owned unreaped process group is signalled. Broad device process output is not retained; the supervisor records its selected ownership observations.

Strict JSON decoding rejects duplicate keys and nonfinite values in the adapter and its supervisor admission/receipt reads. Exact typed comparisons protect the new bias/dependency records and prior registration. Existing inert harness transport is a separate, root-reviewed test interface, not a production authority. All new parsing/binding changes require actual causal controls; the supplied source case table is not evidence that they pass.

Historical campaigns and evidence are not reopened. No old original clock is reset, and no old acceptance supplies a same-stage prior pass. A wrong-target rejection requires a preceding actual selected proof pass and its own causal compiler stream. A generic operational failure supplies no such credit. Public materialization must retain complete input and negative histories; private source-author locators and the predecessor interruption record remain in ignored storage.
