# Judge for three archived finite formulas

Sepehr Mahmoudian, 2026

This package defines the acceptance test for three fixed source files. The question is whether a stock Lean kernel can check that every full, well-typed assignment successfully evaluates each original pair of assertions and that the pair cannot both be true. This preparation contains the judge and empty proof slots. The source-only command does not evaluate an original assertion or inspect a candidate.

## Terms and source identity

A **bit vector** is a fixed-length array of bits. Bit 0 is the least significant bit. A **valuation** supplies a value of the declared sort to every free variable. Each script has 25 such variables, including 16 unrestricted mathematical integers. A **projection** retains one seven-bit input or two four-bit inputs. A **reification** states that a separately specified finite expression returns the same ordered result as the source interpreter. The result type distinguishes evaluation failure from a successful pair of Boolean values. The interpreter, source grammar, bit-vector operations, command order and definition scope are fixed by the archived input and the checked-in model. [Source bindings](bindings.json) · [Shared interpreter](../three-source-w02/lean/W02Semantics.lean) · [Projection definitions](../three-source-synthetic-projection/lean/ProjectionCore.lean)

| Original | Projected variables | Required evidence |
|---|---|---|
| W01, carrier complete | Seven-bit family `a`, 128 masks | The source functions `valid` and `canonical` both return the same Boolean on every assignment. The ordered assertion result is `some [true,false]`. Canonical membership refers to the literal family list in this source. |
| W03, reflexivity | Seven-bit family `a`, 128 masks | The ordered result contains the source validity value followed by the negation of the source order predicate at `(a,a)`. At least one result must be false for every assignment. The validity value is an input-dependent predicate. |
| W15, full joint event | Four-bit cells `k,r`, 256 ordered pairs | The source event at family mask 64 equals the conjunction of equalities for bits 3, 2 and 1. Its right operand is retained as a term from the original source. The ordered assertion result is `some [true,false]`. Bit 0 is outside the comparison. |

Two source readers recover the complete concrete tree and contiguous token spans from the exact original bytes, then independently annotate all sorts. A third reader parses the literal-only Lean module. All three original scripts have 89 commands in their original order. Both final assertions, all 25 declarations, all 57 definitions, the echo, the satisfiability command and the exit remain in the source binding. The three cases use separate source and compiled-module roots so each can retain the previously read-back bytes declaring `SmtW02.originalScript`. The judge never uses echoed results as proofs. ## Acceptance

Each case contains 86 structural step slots, including one identity for the literal command sequence and one static transition for each of 85 active commands. Sixteen further named proof slots cover the folded static result, well-formedness, existence, the full projection and reification, the two source-predicate relationships, the finite decision, ordered success and lack of a satisfying assignment. The projection equality quantifies over every assignment, including every integer and every omitted finite coordinate. Fifteen separate typed consumers name their precise proof dependencies. The final observer records theorem types, proof values, module owners and direct and transitive axioms for all 117 case and consumer declarations plus 15 named supporting theorems per case. A complete result requires the exact original finite test for that case to appear in a checked proof. The hosted judge first compiles the shared artificial positive controls and freshly rechecks their consumer and satisfiability/refusal witnesses. Four false declarations must produce the specified native compiler errors at the registered files and lines, emit no object and match their precise diagnostics. These cover a wrong projected input, a wrong fixed result, a no-model proof used for another script with a satisfying valuation, and confusing evaluation failure with successful refutation. Sixteen previously qualified small sources enter this stage. Two short trace modules also check all four Boolean pairs, failure and two wrong output arities. The different large artificial script is not rebuilt. [Previously fixed control criteria](../three-source-synthetic-projection/plan.json)

After each case’s full-valuation proof and consumers pass, the native judge issues a separate stock reduction for each projected input in numerical order. The second coordinate varies fastest for W15. The trace preserves both Booleans. Code 3 means both are true and code 4 means failure or wrong arity. W01 and W15 require code 2 on every input. W03 retains its actual ordered pair on each mask and requires successful refutation throughout. This execution measures the reified expression. Its statement-level correspondence to full script evaluation is checked separately. [Ordered trace and code reader](finite_trace.py)

The native campaign uses the stock Linux x86-64 release of Lean 4.34.1, source revision `5045d0056413266e57c625dcd7c365b10e377c52`. It verifies the official archive SHA-256, the binary-reported source revision and the source/object membership. It compiles each case in its own module path, runs `leanchecker --fresh` for every ordinary source, proof group and consumer, and reads both independent native output streams. Any unexpected compiler diagnostics fail the relevant check. The standard axiom allowlist consists of `propext`, `Classical.choice` and `Quot.sound`. The native report names the actual direct and transitive use for each theorem. The observer and stock checker share the compiler, interpreter, definitions and release. Ordinary compiled imports retain their recorded import trust. The stock checker’s treatment of axioms, unsafe declarations and partial definitions remains part of the trusted software boundary. ## Running the source check

From a checkout containing the judge, use Python 3.11 or later. Set `EXPECTED` to the package manifest digest in the independent workflow, and choose a fresh output path outside the checkout. This command reads only source structures and constructs no original proof.

```sh
python3 -I -S -B audit/research/three-source-original-first-three/run.py \
  --check-sources --expected-manifest "$EXPECTED" --output "$NEW_SOURCE_REPORT"
```

A native run requires a later, separately authorized attempt registration before any original candidate file exists. The registration occupies `audit/research/three-source-original-first-three-attempt.json` in an earlier Git commit. It binds the judge manifest, separate workflow SHA-256, immutable input preparation, three allowed file paths, exact stock archive and fixed limits. The science commit may change exactly the three candidate files relative to that registration. The registration binds one launch event in its `launch_event` field. A push uses the single reserved branch `review/three-source-original/<40 lowercase hexadecimal registration commit>-<64 lowercase hexadecimal registration SHA-256>`. The workflow path filter names the three proof files, and both the first step and the judge check the complete branch suffix. The native judge also compares the platform event’s branch and after-commit to its checkout. A manual dispatch uses the same two registration identities as explicit inputs. Both routes require the same registration, ancestry, complete three-file diff, budget and pinned sources. A judge-only change on an ordinary review branch cannot start the scientific test. The operator records the original run ID and any duplicate request. A retry or separate invocation cannot earn another original attempt. [Hosted workflow](../../../.github/workflows/three-source-original-first-three.yml)

The process group runs one native command at a time, with 900 seconds per command, a 4 GiB sampled group RSS limit, 5,400 seconds for the campaign and 1 GiB of retained sources, objects and logs. The outer job limit is 100 minutes. The downloaded release and its verified extraction occupy separate temporary supplier storage. A case-level proof failure is retained and subsequent cases may proceed within the same package budget. A resource-boundary stop ends the campaign. Case acceptance requires final custody checks and a retained report. All scientific inputs and expected satisfiability labels are historical. The procedure offers deterministic evidence for the selected formulas and model only. It grants no outside human review, general solver qualification, connection to a PID estimator or result for remaining formulas.

## Rust implementation and computational cost

This project-defined judge reads three fixed command sequences and produces no Rust estimator or patient, sensor or population inference. There is no production Rust API or feature gate for this proof procedure. Source reading scales with the input and constructor trees within the readers’ size and depth bounds. Static transition proofs are partitioned into groups of eight, with a shorter final group. The finite reference tests have exactly 128, 128 and 256 inputs. Their runtime depends on proof terms, stock-kernel reduction and the size of the individual source bodies. Native time and memory for the original proofs require actual execution.
