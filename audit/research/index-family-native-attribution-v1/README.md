# Native attribution for the fixed artificial index study

Sepehr Mahmoudian · 21 November 2026

Which exact hosted run, stock programs and theorem assumptions produced a result? This operational check supplements the fourth artificial index study. The study keeps its 97 source files, 87 term observers, 170 declarations, 254 required direct dependencies, 332 numerical comparisons, three false controls and resource limits. An *artifact* is the ZIP retained by the hosted workflow. A *digest* is a SHA-256 identity for given bytes. A *transitive axiom set* lists the axioms on which a theorem depends, including dependencies through other declarations. An *affinity list* identifies the Linux logical CPUs on which a process may run. A complete positive result requires the genuine first hosted event, the matching ZIP, all original V4 checks and the additional identity comparisons. Execution of the artificial fixture exercises the reader only. An unsuccessful or incomplete event receives no positive attribution. Retain its original terminal and any available output. A matching source hash identifies a file. It does not establish execution of that file. A missing terminal field leaves the corresponding native identity unobserved. The routine assumes independent retrieval of the remote records. Supplied JSON alone cannot authenticate its own origin.

## Rust implementation and computational cost

This is offline evidence processing. It has no statistical sample or Rust estimator. It retains V4's check of at most 550 archive entries and 1 GiB each for compressed and expanded evidence. It reads the registered sources and raw output. Full replay uses the unchanged V4 verifier. The local self-test runs no native Lean command. No new native runtime measurement is reported here.
