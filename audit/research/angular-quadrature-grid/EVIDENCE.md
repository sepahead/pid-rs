The question is whether two finite calculations cover the specified rational amplitude pairs. The source and target variables, averages, units and bounds are defined in the [report](EXPOSITION.md). ## Counting and arithmetic checks

The earlier filter used a 67-point sequence from NumPy, the Python package for numerical arrays, from −0.99 through 0.99. On NumPy 2.4.6 its lower region contained 2,244 pairs and the remainder region contained 1,852. A check with NumPy 2.5.5 found the same eight omissions. A controlled nonfinite calculation left both earlier minima at positive infinity and printed a success message. A finite failed comparison could also print failure and return success to its caller. Those outcomes remain evidence about the earlier program. The current program chooses integers before division, refuses empty and nonfinite comparisons and exits with failure if a margin falls below the tolerance. Each complete ordinary and optimized run returned the same record in JavaScript Object Notation (JSON). A source-only change removed a terminal blank line. It preserved the syntax tree with its source locations and all eight rerun observations. [Diagnostic](quadrature.py) · [Integer and floating-point filters](verify.py) · [Original missing indices](historical-grid.json)

The calculation scans a square and selects its integer diamonds. A second procedure constructs whole rings from nonnegative splits and all distinct signs. Its sorted integer pairs match the two reported SHA-256 values. Each digest uses decimal indices separated by a comma and terminated by a line feed. The original six tests changed a count, a digest, a minimum coordinate, two nonfinite numbers and a margin below tolerance. Six separate input changes to the calculating program tested a negative margin, invalid arithmetic, infinity, an empty comparison and two corrupted tail calculations. Ordinary and optimized Python both refused those changes.

A later check found five records that passed the earlier reader. One replaced a worked atom by −42 nats. One replaced the smallest tail margin by 100 nats. The other three used true and false as indices, repeated a field with two values, or omitted a worked bound. The numerical program and the published numbers were unchanged. The revised reader checks the field names and types, rejects repeated fields and compares every value with its selected reference. The 16 altered-record tests include the original six. The default reference is the published calculation, which has a fixed 256-bit Secure Hash Algorithm (SHA-256) digest. The fresh reference is a new execution of the original numerical source with local NumPy. Matching a fresh record requires agreement on both smallest margins, their indices, all worked values, the two rosters and the software version. A different NumPy build can produce a different valid local result. The code supplies no bound on numerical integration error. A direct per-power calculation and the slab polynomial were compared at $(1/4,1/4)$, $(1/2,0)$ and $(-0.63,0.18)$, where the coordinates are the two dimensionless amplitudes. Across the three pairs the largest absolute difference in either joint mean was $5.56\times10^{-17}$ nats after rounding up. Agreement at these points leaves the numerical error at other points open. The finite test tolerates a signed residual of $-10^{-15}$ nats. The analytic bounds come from the separate real-valued derivation.
