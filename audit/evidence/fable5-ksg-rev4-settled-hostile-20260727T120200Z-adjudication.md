# Fable 5 Max revision-4 hostile-review adjudication

Status: **advisory review record; not claim evidence and not a gate receipt**.

This record adjudicates five completed Fable 5 Max responses against independent source inspection,
exact arithmetic, executable counterexamples, and the candidate worktree. A model allegation is not
accepted because it sounds plausible. It enters the repair set only when a separate route reproduces
the proposition. Failure to find a counterexample is not proof.

## Captured review lenses

The completed calls covered five failure-diverse roles: proof/SMT correspondence, binary64 and
compiled refinement, source-blind algebra, checker-hostile formal methods, and a second binary64 /
compiled-refinement pass. Every call received the same 2,053,279-byte captured context. Three other
configured aliases were already out of credit; the two initially viable aliases were then run until
they too returned `credit_exhausted`. Exact response and receipt hashes are bound by the companion
completion receipt.

## Accepted findings, after independent reproduction

1. **Compiled full-corpus partition gap.** The Rust regression asserted endpoint positive zero,
   association diagnostics, the rounded-reference maximum, and swap symmetry, but it did not
   directly classify all 8,198 selected outputs as `+0/-0/nonzero = 354/0/7844`. Python did. The
   prose said both routes directly derived the partition. The repair adds finite-value checks and a
   direct raw-bit classification over every Rust row. This is fixed-corpus correspondence, not a
   portable binary64 or estimator theorem.
2. **SMT-LIB shape/firewall gap.** The old validator was based partly on raw substrings. Independently
   reproduced digest-rebased files could append `(assert theorem_holds)`, use whitespace-token
   variants, or add unsupported commands while retaining misleading positive/negative solver
   behavior. A stronger wrong-theorem control replaced the digamma theorem by a mutation-offset
   equality; its SHA-256 was
   `88e67f4289caf81770c9457d3ac77de4f470fe56d8bf3eb0a8139ac42c23ec52`. It preserved the old
   positive SAT preflight, made the negative route UNSAT, and left the 12 existing semantic mutants
   SAT after a raw-digest-only rebase. The repair therefore needs a bounded parser, exact ordered
   proof profiles, sequential sort/arity checks, immutable one-read snapshots, revalidated positive
   derivation, and solver input over standard input. Parser/profile controls remain distinct from
   the 12 mathematical countermodels.
3. **JSON bool/integer coercion.** With certificate digest and sidecar deliberately rebased, the
   modular checker accepted `certificate_revision: 1 -> true` (mutant SHA-256
   `ab8940978e664c1da73811a42e5eeeb91b8a919f4d650a1b39142c59d828e3d4`) and
   `include_zero_residues: true -> 1` (SHA-256
   `caab3e6f4f1da9c9d5793806446c78e4b4288e6e61593e96e36208dbd60b509b`). Both normal and
   optimized Python exited zero. Recursive path-aware exact type/shape/value comparison is required.
   These firewall controls do not increase the mathematical mutation count.
4. **Finite-Decimal comparator exactness.** The reported `8.18e-77` maximum is correct for the frozen
   bytes, but the old comparison used a 160-digit Decimal context without enforcing exact
   subtraction. An independent full-corpus replay found 8,198/8,198 exact subtractions, with no
   `Inexact` or `Rounded` signal. Exact `Fraction(Decimal)` reconstruction gives row 7952
   `(65536,64,32799,32799)` and distance `818/10^79 = 409/(5*10^78) = 8.18e-77`; row 7927 is the
   runner-up at `8.03e-77`. The repair makes exact rational ordering explicit rather than relying on
   this corpus happening to fit the Decimal context.
5. **Statistical-independence wording.** The `isx.rs` comment “Each point is independent” described
   implementation-local scratch, not a statistical independence assumption. The implementation
   comment now states only the no-cross-index-mutable-state proposition.
6. **Machine argument-order ambiguity.** W1/W2 packet arrays are `(k,n,x,y)`, while C30 is explicitly
   `(n,k,x,y)`. The W1/W2 keys need an order suffix; numeric values do not change.
7. **Runtime constraint scope.** Under an eligible positive unique kth shell, finite max-product
   distances, strict-radius/predecessor equivalence, and the exact route-specific count map, a set
   argument gives `x+y <= n+k`. The argument was independently reconstructed for the inventoried
   KSG, ISX, and PID3 routes. It remains a conditional source lemma, not a promoted revision-4
   project theorem; the balanced stronger lower bound remains unpromoted until its exact, formal,
   compiled, mutation, and provenance routes close.
8. **Modular reflection mechanism.** Elementary inverse pairing gives
   `H_(p-1-t) = H_t (mod p)`. For rejected `p=1000003`, `999999=p-4`, so the four retained
   collisions are the same forced `H_999999-H_3` event up to sign. This is not Wolstenholme's
   theorem. The selected primes share this structure and are redundant certificate lanes, not
   independent proofs.
9. **Lifecycle chronology.** A superseded section called `afc45ff27e5af7fe04e44f2bb9f4147fb472c81e`
   “M1a,” while the live authority correctly treats the settled-byte M1a anchor as future. The live
   resume must explicitly classify that hash as an earlier provisional checkpoint.
10. **Review-context wording.** The runner intentionally excluded its generated output family from
    `changedPaths()` to avoid self-reference, but the context header said its manifest covered every
    untracked file. That sentence is false for the contemporaneous status. The original context is
    retained byte-for-byte; the companion completion receipt narrows the manifest to captured input
    paths and binds all completed output bytes.
11. **Minor label drift.** One revision checker error message says “reviewed revision-3 digest” for
    the schema-2 revision-4 generator digest. The digest itself was correct; the label needs repair.

## Rejected or narrowed findings

- The reviewers' auxiliary lower bound `min nonzero |T| >= 1/999999` is false on the frozen corpus.
  The exact minima occur at rows 8177 and 8185, tuples `(1000000,500000,500000,999998)` and its
  source swap, with magnitude `499999/499999500000`, approximately `9.99998999999e-7`. No such
  lower bound is used in the repair; the direct partition is asserted instead.
- The claim that corpus index 33 is absent is false. Indices 37 and 81 are absent, but absence or
  isolated co-occurrence reasoning is not a selected-prime separation proof. Exhaustive recomputed
  nonzero residue vectors in the certificate remain the authority.
- The phase checker uses some type-lax local comparisons, but a one-field policy-digest rebase alone
  did not produce the alleged complete false green: a later changed-projection hash still failed.
  The schema/authority comparison is nevertheless hardened as defense in depth.
- The `.gitignore` leading-slash concern was rejected by a direct Git fixture comparison. The
  `0644/0755` mode restriction is an intentional canonical-permission policy, not an accidental
  portability claim.
- The Lean `opaque` allegation does not bypass the load-bearing per-theorem `#print axioms` gate.
  Parser-format hardening and a concrete premise witness remain useful follow-up controls but were
  not shown to invalidate the 19 current theorems.
- The kd-tree `i as u32` concern omitted the explicit `n > u32::MAX` rejection in
  `KdTree::build`; the cast occurs only after successful tree construction. No truncation defect was
  reproduced.
- The release-corpus coverage concern omitted CI's `release-numerics` job, which runs
  `cargo test --locked --release -p pid-core --all-features`; the corpus unit test is included.
- `git diff --check` means a whitespace-error scan, not an assertion that the worktree diff is empty.
- Swap symmetry and signed-zero counters are structural canaries with limited fault-discrimination;
  they remain honestly scoped and are not treated as independent evidence.

## Disposition

No Fable response produced a valid counterexample to the bounded exact arithmetic identity, sharp
rectangular bound, frozen-corpus counts, W0/W1/W2/W2b values, or the one-way modular implication.
That negative search is corroboration only. The accepted checker and compiled-evidence defects are
real and keep repository/publication integration at **NO-GO** until repairs are settled, replayed,
resealed, independently reviewed, committed, pushed, and bound by the M1a/M1c lifecycle.

This review has no bearing on KSG estimator consistency, continuous shared-exclusions validity,
PID2/PID3, MGW SxPID, support assumptions, calibration, portability, or downstream consumer
fitness.
