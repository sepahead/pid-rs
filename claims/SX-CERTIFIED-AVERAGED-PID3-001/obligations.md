# Obligations for SX-CERTIFIED-AVERAGED-PID3-001, revision 1

## Target and dependency graph

The target is a deterministic per-input certificate implication, not a population-estimator
theorem. Its load-bearing graph is:

```text
S1 primary-source identity
  -> D1 canonical input semantics
  -> D2 MGW OR-of-AND event plus target intersection
  -> L1 complete 18-antichain carrier
  -> L2 order, zeta orientation, and exact Mobius inverse
  -> A1 54 cumulative products
  -> A2 54 atom products and 108-coordinate registry
  -> B1 boundary/sign/zero semantics

F1 Lean concrete semantics ---------+
F2 independent SMT finite algebra --+-> formal gate

N1 exact-product comparison --------+
N2 independent log enclosure -------+-> numerical-certificate gate
R1 preflight/resource semantics -----+

X1 producer conformance -------------+
X2 independent verifier refinement --+-> executable gate
X3 compiled Rust keyed refinement ---+

Q1 bounded 20,348-table replay ------+
Q2 metamorphic closure --------------+-> fault-sensitivity gate
Q3 retained semantic mutations ------+

P1 immutable source/toolchain/evidence binding
H1 independent acquisition and custody
  -> final adjudication
```

No downstream node may be called independent of an upstream node it imports. In particular, two
programs that import the same event predicate or generated matrix share that cut.

## Critical cut sets

The minimal shared cuts currently include:

1. **C-MGW:** the paper-to-formula mapping for the event, component split, averaging, and order;
2. **C-DECODE:** canonical bytes to exact supported count table;
3. **C-EVENT:** input rows to all $U_{\alpha,z},V_{\alpha,z},T_z$;
4. **C-LATTICE:** stable antichain key to order, zeta row, and Möbius row;
5. **C-PRODUCT:** count-cleared expression to normalized positive rational;
6. **C-LOG:** exact rational to outward real-log interval;
7. **C-EXEC:** reviewed source to the executed producer/verifier/Rust binaries; and
8. **C-EVIDENCE:** complete first-result and mutation receipts to the decision record.

Each route memo must identify which cuts it shares and direct at least one falsification attempt at
each shared cut. Reimplementing downstream arithmetic does not diversify an imported event or
lattice cut.

## Exceptional-case disposition

| Exceptional case | Revision-1 treatment |
|---|---|
| Zero-count cell | Omitted from positive support; never evaluated as $0\log0$ |
| Empty table or zero total | Reject |
| Duplicate complete state | Reject before event counting |
| Event denominator zero | Impossible for a valid supported key; reject if observed |
| Exact product one | Exact zero, even for a nonempty factor expression |
| Negative signed-net atom | Valid; preserve without clamping |
| Informative/misinformative negative atom | Treat as a semantic/refinement failure for the full paper-defined lattice, not by silently clamping |
| Integer/resource overflow | Preflight abstention/rejection; never partial verification |
| Floating interval intersects zero | Exact product lane decides; interval alone is unresolved |
| Pointwise output | Out of scope |
| Continuous, singular, or mixed-dimensional law | Out of scope; do not route through this categorical claim without an explicit fixed quantizer and new estimand identity |
| Fitted quantization | Out of scope; requires a separately fitted/frozen transform claim |
| Dependent rows or drift | No effect on the deterministic empirical functional; population or sampling inference remains out of scope |
| Platform transcendental differences | Enclosed by the two directed routes or verification rejects |

## Acceptance invariant

`verified` is a single terminal status. It is unavailable unless every one of the 108 identities
has:

1. independently reconstructed exact event counts and products;
2. an exact product equality with the certificate object;
3. an exact zero/strict-sign decision;
4. an independent interval contained in the producer interval;
5. a passing coordinate, lattice, source, input, and resource binding; and
6. no partial, skipped, unknown, exhausted, or unbound substatus.

No total or percentage may average a failed or open coordinate into acceptance.
