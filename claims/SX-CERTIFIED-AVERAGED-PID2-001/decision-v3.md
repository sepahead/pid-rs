and, only where status is `compared`, the unchanged exact rational-product zero/strict-sign

## Why the verifier revision is justified

1. The observed CPython 3.11.15 job rejected through the integrity guard before crediting an
   accepted result.
2. The changed digest route primes the specific nonsemantic string-intern state before both the
   initial and later live-code serializations.
3. A dedicated two-copy control requires equality between cold and explicitly interned instances
   of the qualified cache state.
4. A distinct control replaces live function code and requires the integrity guard to reject,
   then requires recovery only after restoration.
5. An exhaustive declared-inventory control mutates each of 51 uppercase semantic/configuration
   globals and requires rejection followed by recovery.
6. On CPython 3.11, an isolated source mutant removes the normalization call and must reproduce
   the intended integrity rejection.
7. The schema and digest-domain revisions prevent old and new digest semantics from being silently
   treated as the same verification object.
8. No event, lattice, expression, rational-log, interval, product, resource, or PID semantics
   changed.

These points support the narrow source-level re-adjudication. A fresh public green CI rerun,
catalog/projection closure, assurance-paper/PDF update, full containing commit, and independent
custody are still open and must not be inferred.

## Required runtime interpretation

The verifier's source digest is an exact-byte digest. Its loaded-execution digest is a
project-defined drift detector for inspected module-owned functions and critical constants under
the report's Python implementation/version. The normalization removes the named cache-state
artifact only; the typed inventory binds the 51 reviewed uppercase semantic/configuration
globals. It does not establish:

- source-to-bytecode refinement;
- Python or process correctness;
- equality across runtimes or marshal formats;
- semantic equivalence of different code objects;
- executable provenance, authenticity, or custody; or
- completeness against every live-state mutation.

## Open obligations preventing stronger wording

- CPython, arbitrary-precision integers, `Fraction`, `sys.intern`, `marshal`, JSON, SHA-256,

- No statistical, population, application, or downstream qualification is part of this decision.
